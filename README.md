# КАТЕКС — учет инструмента

## Обновление от 20.10.2026

Исправлены связанные исправления/отмены приёмки после переточки, конкурентные расходы, скрытие отрицательных остатков, выполнение скриптов из справочников, фильтры отчёта, регистр кириллицы в поиске и дробный радиус. Добавлена защита от повторной отправки форм.

В разделе «Учёт и движение» показывается одна выбранная операция. Перед проведением открывается подтверждение с количеством, получателем и ожидаемым остатком. Есть быстрые действия из карточки, мобильные карточки каталога, меню для телефона, дополнительные фильтры и выбор результата поиска с клавиатуры. Ошибки отправки показываются в форме без потери введённых данных. При сдаче количество указывается явно.

### Обновление существующей установки

1. Остановите приложение и сохраните резервную копию всей папки `data` (включая фото).
2. Распакуйте новую версию в отдельную папку. Перенесите в неё вашу папку `data` либо оставьте прежний путь в `TOOLSTOCK_DATA` / `TOOLSTOCK_DB`.
3. Запустите обычным `start.bat` / `start.sh`. При старте автоматически добавится служебная таблица защиты от дублей; карточки, пользователи и движения сохраняются.
4. Обновите открытые вкладки браузеров: старые формы не содержат нового идентификатора запроса и будут отклонены.

Новая версия предотвращает обнаруженные ошибки, но не переписывает ошибочные движения, уже созданные прежней версией. Если есть расхождения, сначала сверьте их с фактическими остатками. Отрицательное значение теперь отображается как ошибка учёта. Связанная приёмка с уже нарушенным количеством блокируется для обычного исправления, чтобы не скрывать расхождение.

`app.js` должен находиться рядом с `app.py` и `style.css`. База и тестовые учётные записи в архив не включены. Для запуска приложения по-прежнему достаточно Python 3.10+.

### Проверки

Регрессионные тесты используют стандартную библиотеку и временные базы, не изменяя рабочую папку `data`:

```sh
python -m unittest discover -s tests -p "test_app.py" -v
```

Необязательная браузерная проверка требует установленного Playwright и Chromium:

```sh
python tests/browser_smoke.py
```

Путь Chromium можно указать переменной `CHROMIUM_PATH`; для результатов и снимков — `TOOLSTOCK_TEST_OUTPUT`. По умолчанию браузерный тест использует `/usr/bin/chromium`; на Windows укажите свой путь. Это зависимости только для тестирования, не для работы приложения.


Программа оформлена в фирменном стиле КАТЕКС; логотип отображается в меню и на экране входа.

Переносимый MVP складской системы для локальной сети. Приложение написано на Python 3.10+ и использует только стандартную библиотеку. Внешняя база данных, установка пакетов и интернет для запуска не требуются.

## Запуск в Windows

1. Установите Python 3.10 или новее.
2. Распакуйте архив в отдельную папку.
3. Запустите `start.bat`.
4. На компьютере склада или другом компьютере локальной сети откройте `http://IP-АДРЕС-КОМПЬЮТЕРА-СКЛАДА:8000`. При первом запуске создайте администратора. Первичная настройка доступна по сети только до создания первой учетной записи; создание защищено от одновременной регистрации нескольких администраторов.

Для работы с других компьютеров локальной сети откройте `http://IP-АДРЕС-КОМПЬЮТЕРА-СКЛАДА:8000`. Разрешите входящие подключения к порту 8000 в брандмауэре Windows.

Ограничьте правило брандмауэра локальной сетью: во время первого запуска любой компьютер, который может открыть этот адрес, сможет создать единственную учетную запись администратора. После ее создания форма первичной настройки отключается.

Linux/macOS: `./start.sh`, затем откройте адрес сервера на порту 8000.

## Что работает

- Роли администратора, кладовщика и рабочего, а также пользовательские роли с выбранными правами. Раздел «Учетные данные» доступен только администратору.
- Каталог инструмента и оснастки. Коды создаются автоматически; инвентарный номер используется только для оснастки. Категории можно выбрать из списка или добавить свою.
- Карточка показывает параметры по выбранной категории: пластины — ISO 1832 или ручное обозначение для канавочного, отрезного и резьбового исполнения; для пластин также можно указать тип стружколома и материал. Для корпусного режущего инструмента задаются обозначение устанавливаемой сменной пластины и число гнезд.
- Для резьбофрез, метчиков и плашек задаются тип и параметры резьбы; для осевого инструмента — подача СОЖ. Для токарной оснастки доступны блоки BMT/BOT/VDI с размерами A–H, держатели с D/H/H1/L и переходные втулки. Для фрезерной оснастки доступны оправки, патроны, цанги, тиски, угловые головки и расточные системы с диапазоном, точностью и составом набора.
- Для инструмента можно указать несколько групп применяемости ISO 513: P, M, K, N, S и/или H. Для ISO-пластин обозначение формируется автоматически по семи полям ISO 1832 / ГОСТ 19042. Модель или обозначение производителя показывается первым в каталоге и поиске поступления; общее наименование отображается дополнительной строкой.
- В каталоге Ø, l1 и L сортируются нажатием на заголовок столбца. Количество, стоимость и число зубьев задаются целыми числами; для размеров инструмента, шага резьбы и точности оснастки разрешены дробные значения.
- В карточке позиции хранится стоимость одной штуки.
- Пластины с одинаковым семипозиционным ISO-обозначением и разными производителями группируются в каталоге: общий остаток суммируется, а «Показать все» раскрывает карточки производителей. Запас на складе отображается цветной шкалой от красного к зеленому.
- Поступление на склад, выдача рабочему с проверкой его станка, возврат БУ отдельно от нового инструмента, списание у рабочего и списание со склада.
- В операциях карточки ищутся по мере ввода названия, кода, модели, категории или производителя. Новую карточку можно создать прямо в форме поступления; такое поступление всегда учитывается как новое. При выдаче отображаются остатки и место хранения, а при наличии нескольких состояний появляется выбор состояния. Выдача и списание используют тот же поиск.
- Переточка проходит этапами: сдача рабочего в очередь → экспорт или массовая отправка всей очереди → прием после переточки. При приеме создается отдельная карточка с измененными Ø и l1 и отметкой «Перетачивался»; исходная карточка остается без изменений.
- Остатки разнесены по состояниям: новый, БУ, после переточки, ожидает отправки и находится на переточке.
- Журнал движений с датой, автором операции, количеством, рабочим, станком и комментарием. Исправления и отмены отмечаются отдельно и сохраняют причину и снимок изменений.
- Отчеты по текущим остаткам, рабочему, станку и периоду. Рабочие могут быть закреплены за несколькими станками; фильтры отчета синхронизируют рабочего и станок, а выбор рабочего показывает только позиции, которые числятся за ним сейчас. Выгрузка остатков и истории в CSV для Excel.
- Раздел заявок на закупку показывает позиции с доступным остатком ниже минимума, включая нулевые остатки. Количество можно скорректировать перед сохранением заявки; готовую заявку можно выгрузить в CSV с расчетом суммы по стоимости из карточки.
- Справочники станков, рабочих и учетных записей.
- Станки и данные рабочих можно редактировать в справочнике. Закрепление рабочих за станками выбирается отдельными чекбоксами; можно отметить несколько станков.
- Матрица ролей и разрешений; администратор сохраняет полный доступ.
- Учетные записи, станки и рабочие отключаются действием «Удалить», сохраняя историю; отключенные записи можно восстановить в разделе администрирования. Рабочего с инструментом на руках удалить нельзя — сначала примите или спишите инструмент.
- Одинаковые обозначения основного и переточенного инструмента объединяются в каталоге с общим остатком; по «Показать все» доступны подробные карточки. В поиске выдачи варианты после переточки помечены отдельно.
- Для карточек после переточки минимальный остаток автоматически равен нулю. Изменять их характеристики может только администратор; кладовщик принимает инструмент с параметрами, заданными администратором.

## Первоначальная настройка

После входа администратором откройте «Учетные данные». Добавьте станки, затем рабочих с их закрепленными станками, затем учетные записи кладовщикам и рабочим. Здесь можно редактировать права ролей и удалять пользовательские роли, не назначенные активным учетным записям. Карточку можно создать в каталоге заранее или сразу в форме поступления; обе формы используют одинаковые динамические параметры категорий.

Для рабочего учетную запись нужно связать с карточкой рабочего. При выдаче кладовщик выбирает рабочего; станок подставляется автоматически из его карточки. При сдаче сначала выбирается рабочий, после чего приложение показывает его текущие позиции и фактическое количество. Сданное количество можно вернуть как БУ, направить в очередь на переточку или списать. Количества, минимальные остатки и стоимость за штуку задаются целыми числами. Радиус, диаметр и длины инструмента допускают дробные значения; при серверном вводе геометрии поддерживается десятичная запятая. Для шага резьбы и точности оснастки также поддерживаются дробные значения. Каждая операция сохраняется в журнале.

Операцию можно исправить или отменить в журнале движений в течение 24 часов после проведения. Для действия требуется указать причину. Приёмка после переточки исправляется или отменяется сразу в обеих связанных карточках. Изменение отклоняется, если оно нарушает остатки в последующих операциях; исходная запись и история исправлений сохраняются.

## Данные и резервное копирование

База создается в `data/toolstock.sqlite3`, фотографии — в `data/photos`. Для резервной копии остановите сервер и скопируйте папку `data` целиком. Папку `data` не следует пересылать вместе с исходным архивом, если база содержит производственные данные.

## Ограничения MVP

- Каталог из Excel и история книги автоматически не импортируются. Перед переносом нужно сопоставить колонки исходных листов с карточками и движениями, затем сверить начальные остатки.
- CSV-выгрузка открывается в Excel; экспорт `.xlsx` пока не реализован.
- Приложение рассчитано на проверку процесса и небольшой локальный контур. Для постоянной работы на нескольких рабочих местах следует добавить HTTPS, резервное копирование по расписанию, журнал аудита администрирования и PostgreSQL.
- Удаление движений не предусмотрено. Ошибочные записи корректируются обратной операцией с комментарием.

## Настройки

Переменные окружения: `TOOLSTOCK_HOST` (по умолчанию `0.0.0.0`), `TOOLSTOCK_PORT` (8000), `TOOLSTOCK_DATA` (папка базы и фото), `TOOLSTOCK_DB` (путь к SQLite-файлу).
