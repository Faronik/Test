# Проверка версии 2.0

Проверено в этой задаче на Linux, в Docker Compose с PostgreSQL 17. C++20-сервер собран GCC 12 из Debian 12; ресурсы и миграция работают от пользователя контейнера UID 10001. Исполняемый контейнер не содержит Python. Windows-скрипт подготовлен, но запуск Docker Desktop на Windows здесь не испытывался.

## Выполненные проверки

- Сборка CMake и финального многостадийного Docker-образа; запуск app + db; PostgreSQL readiness и HTTP `/health`.
- **34 API-теста** (`tests/api.mjs`): настройка, вход, права, CSRF и методы HTTP; каталог, кириллица, дробные размеры; поступление/выдача/возврат/списание; переточка и обе стороны исправления; откат после последующего расхода; параллельные расходы и дубли; фото; заявки/CSV/архив; защита последнего администратора; SQL-параметры и текст со скриптами.
- **7 отраслевых/API-проверок** (`tests/domain.mjs`): ISO-пластина и семипозиционное обозначение; недопустимые ISO/материалы; резьбовая пластина; метчик и СОЖ; оснастка и уникальность инвентарного номера; точный снимок массовой отправки; смена пароля и прекращение сеансов.
- **20 браузерных проверок** (`tests/browser_cpp.py`, Chromium): вход, карточка с фото и длиной/дробным радиусом; поступление, выдача, частичный возврат, полный цикл переточки; подтверждение остатка; мобильный каталог и выравнивание кнопки; создание карточки из поступления; заявки, завершение и архив; справочник; отчёты; интерактивная документация API; отсутствие ошибок JavaScript.
- **9 проверок переноса** (`tests/migration.mjs`, Node.js 24): импорт SQLite в отдельную PostgreSQL-базу, старый PBKDF2-пароль, роли, характеристики и фото, остатки и закрепление, аудит и завершённая заявка, продолжение ID после импорта. Подтверждены неизменность исходного файла, отказ в повторном импорте в заполненную базу и полный откат при отсутствующей фотографии. Тестовые базы и контейнеры удалены тестом.
- Резервная копия `scripts/backup.sh`: приложение остановлено на время копирования и запущено обратно; PostgreSQL dump восстановлен в отдельную базу. Количество карточек и движений совпало, все фотографии, указанные в восстановленной базе, найдены в архиве фото.

Дополнительно проверены повторный запуск с сохранением карточек и движений, формат времени RFC3339, отказ при цене с долями копейки и сохранение/повторное открытие карточки со своей категорией и дробной длиной.

Проверки используют искусственные данные и отдельные контейнеры/базы. Рабочая база пользователя не предоставлялась и не изменялась. Для реального перехода требуется выполнить импорт копии своей папки `data` по README; готовый импортёр не означает, что производственные данные уже перенесены.

Не выполнялись длительная нагрузка, тест всех возможных полей и комбинаций ролей, проверка на реальном складе, Windows-native сборка и ввод в эксплуатацию на машине пользователя. PostgreSQL и новый API не заменяют проверку собственного производственного процесса перед переходом.
# Проверки нативного запуска 2.1

Проверено на Linux: сборка C++20 (GCC 12), установка пакета через CMake, запуск самого бинарного файла вне контейнера с отдельной тестовой PostgreSQL 17. Прошли 34 API-теста и 7 проверок предметных правил. Проверены ресурсы рядом с бинарным файлом, запуск из другой рабочей папки, пути с пробелами и кириллицей, относительные пути JSON, приоритет конфигурации над окружением, healthcheck, перезапуск с сохранением базы и автоматическое обнаружение настроек. Неверные JSON, порт и неизвестные параметры отклоняются без вывода пароля.

Дополнительно проверен нативный импорт SQLite из пути с кириллицей с непустым WAL: фотографии скопированы, исходная база не изменена, остаток в PostgreSQL совпадает, повторный импорт запрещён. Компиляция интерфейса HTTP проверена как с Debian cpp-httplib 0.11, так и с заголовками 0.62 из закреплённой Windows-зависимости.

Синтаксический разбор четырёх PowerShell-скриптов прошёл. Он не заменяет исполнение Windows. Workflow `windows-native.yml` отдельно собирает настоящий Windows x64 пакет и проверяет API, нативный импорт, установку, обновление, запуск/остановку и удаление службы. Результат Windows-проверок фиксируется в GitHub Actions; выпуск разрешён только после их прохождения. Проверка реальной пользовательской базы и установка на компьютере пользователя не выполнялись.
